    UART 串口驱动 (BSP)

    用途

    UART BSP 使用 DMA 与双缓冲接收不定长数据，并提供回调或任务轮询两种处理方式。需要接入串口设备时，先确认该 UART 的 DMA 资源和缓冲区位置，再按本页选择接收方式、初始化接口和发送接口。

    设计理念

    空闲中断 + DMA 收不定长帧

    接收采用 HAL_UARTEx_ReceiveToIdle_DMA。DMA 自动搬运字节流，总线出现 IDLE（空闲）时硬件触发 HAL_UARTEx_RxEventCallback，天然支持"不知道长度的一帧"——帧结束即空闲，无需上层约定固定长度。

    乒乓双缓冲（Ping-Pong）减少处理窗口

    每路 UART 配两块缓冲区 Rx_Buffer_0/1。Rx_Buffer_Active 指向 DMA 正在写入的那块，Rx_Buffer_Ready 指向已收完可读取的那块。一帧收完时交换两个指针角色，DMA 转到另一块继续接收。上层仍应及时消费就绪缓冲，避免后续帧覆盖尚未处理的数据。

    实例分支 + 单回调的点对点路由

    与 CAN 的 ID 查表注册表不同，UART 是点对点链路。中断回调按 huart->Instance 定位到对应管理对象，直接调用其 Callback_Function。与同工程的 bsp_spi 同构。

    回调可选，支持轮询退化

    UART_Init(huart, nullptr) 时 DMA 照常接收、双缓冲照常切换、时间戳照常更新，但不触发回调；上层任务可自行轮询 Rx_Buffer_Ready 与 Rx_Timestamp，把数据处理放到任务上下文而非中断中。

    错误恢复

    HAL_UART_ErrorCallback 调用 UART_Reinit() 尝试恢复接收链路。若持续出现噪声或溢出，还需检查线路、波特率和上层处理速度。

    核心数据结构

    struct Struct_UART_Manage_Object
{
    UART_HandleTypeDef *UART_Handler;      // HAL 句柄
    UART_Callback Callback_Function;       // 业务回调（可为 nullptr）

    uint8_t Rx_Buffer_0[UART_BUFFER_SIZE]; // 双缓冲 A（512 字节）
    uint8_t Rx_Buffer_1[UART_BUFFER_SIZE]; // 双缓冲 B
    uint8_t *Rx_Buffer_Active;             // DMA 正在写入（不可读）
    uint8_t *Rx_Buffer_Ready;              // 已收完（可安全读取）

    uint64_t Rx_Timestamp;                 // 接收完成时间戳
};

    回调签名：

    typedef void (*UART_Callback)(uint8_t *Rx_Data, uint16_t Length);

    资源约束

    DMA Stream 耗尽

    DMA1 + DMA2 共 16 条 stream，已被 7 路 UART 收发 + SPI + ADC 占满。UART4 / UART8 / UART9 物理上分不到 DMA（BDMA 的 8 通道仅服务 D3 域的 LPUART / SPI6，够不着 APB1 上的 UART4/8/9）。故本驱动只接管具备 RX DMA 的 7 路：USART1 / USART2 / USART3 / UART5 / USART6 / UART7 / USART10。

    半双工 UART5

    UART5 仅有 RX DMA、无 TX DMA。UART_Transmit_Data() 检测 huart->hdmatx == nullptr 时自动回退 HAL_UART_Transmit() 阻塞发送。

    .dma_buffer 内存铁律

    DTCMRAM（0x20000000）不能被 DMA1/DMA2 访问。管理对象（含双 512B 缓冲）使用 __attribute__((section(".dma_buffer"), aligned(32))) 放入专用的 RAM_DMA（0x24000000 起的 64 KiB，不可缓存），而不是普通的 RAM_D1 段。

    RX DMA 模式必须为 NORMAL

    双缓冲范式假设 DMA 搬完即停、由回调手动切缓冲重启。若 CubeMX 配成 CIRCULAR（DMA 永不停），与手动重启语义冲突会导致丢数据/错位。

    数据流向可视化

    接收链路 (Rx Pipeline)

    graph TD
    A[串口字节流到达] --> B[DMA 自动搬入 Rx_Buffer_Active]
    B --> C{总线出现 IDLE 空闲?}
    C -- 否, 继续搬运 --> B
    C -- 是, 一帧结束 --> D[硬件触发 HAL_UARTEx_RxEventCallback]
    D --> E{init_finished?}
    E -- 否, 仅重启接收 --> B
    E -- 是 --> F[Ready = Active, 交换双缓冲指针]
    F --> G[记录 Rx_Timestamp]
    G --> H[在新 Active 上重启 DMA 接收]
    H --> I{Callback_Function != nullptr?}
    I -- 是, 事件驱动 --> J[调用业务回调处理 Rx_Buffer_Ready]
    I -- 否, 轮询模式 --> K[由上层任务自行读取 Ready]

    发送链路 (Tx Pipeline)

    graph TD
    A[上层调用 UART_Transmit_Data] --> B{huart->hdmatx == nullptr?}
    B -- 否, 有 TX DMA --> C[HAL_UART_Transmit_DMA 非阻塞发送]
    B -- 是, 如 UART5 --> D[HAL_UART_Transmit 阻塞发送, 超时 10ms]

    核心 API

    UART_Init

    void UART_Init(UART_HandleTypeDef *huart, UART_Callback Callback_Function);
    参数 说明
    huart 目标串口 HAL 句柄
    Callback_Function 接收回调函数指针，传 nullptr 进入轮询模式

    清零并绑定管理对象，把 Rx_Buffer_Active 指向 Rx_Buffer_0，启动首次 HAL_UARTEx_ReceiveToIdle_DMA。对未接管实例（UART4/8/9）调用被安全忽略（内部返回 nullptr）。

    UART_Reinit

    void UART_Reinit(UART_HandleTypeDef *huart);

    错误恢复或主动重启时，复位 Rx_Buffer_Active 到 Rx_Buffer_0 并重启 DMA 接收。由 HAL_UART_ErrorCallback 自动调用，也可上层手动调用。

    UART_Transmit_Data

    uint8_t UART_Transmit_Data(UART_HandleTypeDef *huart, uint8_t *Data, uint16_t Length);
    参数 说明
    huart 目标串口句柄
    Data 待发送数据缓冲区
    Length 发送字节数

    有 TX DMA 走 HAL_UART_Transmit_DMA（非阻塞）；无 TX DMA（UART5）回退 HAL_UART_Transmit（阻塞，超时 UART_TX_BLOCKING_TIMEOUT = 10 ms）。

    典型使用流程

    事件驱动（推荐用于实时、处理简单的场景）

    void DBUS_RxCallback(uint8_t *buf, uint16_t len) {
    // 轻量处理：取数据、置标志、投递事件
}
UART_Init(&huart1, DBUS_RxCallback);

    一帧到达即在中断上下文触发回调；回调内应只做轻量处理。

    轮询模式（推荐用于处理复杂、需在任务上下文操作的场景）

    UART_Init(&huart1, nullptr);
uint64_t last = 0;
for (;;) {
    uint64_t now = USART1_Manage_Object.Rx_Timestamp;
    if (now != last) {
        uint8_t *data = USART1_Manage_Object.Rx_Buffer_Ready;
        // 在任务上下文从容处理 data
        last = now;
    }
    osDelay(10);
}

    C++ 设备类的转发回调

    C 函数指针不能直接指向 C++ 成员函数，需自由函数中转：

    void DBUS_RxCallback(uint8_t *buf, uint16_t len) {
    BSP_DBUS.UART_RxCallback(buf, len);  // 转调全局单例成员方法
}

    配置参数

    参数 默认值 说明
    UART_BUFFER_SIZE 512 单块接收缓冲区字节数
    UART_TX_BLOCKING_TIMEOUT 10 ms 无 TX DMA 时阻塞发送超时
    接管范围 7 路 USART1/2/3、UART5、USART6、UART7、USART10
    HAL 弱符号覆写 extern "C" .cpp 中覆写 HAL 的 C 弱符号必须加，否则 C++ name mangling 后无法覆盖

    常见问题

    DMA 缓冲区误放 DTCM → 永远收不到数据

    若误把接收缓冲放进 DTCMRAM，DMA1/2 无法写入预期数据。排查时先看 map 文件，确认管理对象位于 .dma_buffer 段，再检查 DMA 状态与 UART 配置。

    RX DMA 被配成 CIRCULAR → 丢数据/错位

    CubeMX 重新生成后务必确认 7 路 RX DMA 仍为 DMA_NORMAL。CIRCULAR 会破坏双缓冲语义。

    中断里执行重活

    事件驱动回调运行在中断上下文，复杂解析请改用轮询模式或在回调内仅投递事件。

    UART4/8/9 无 DMA 可用

    如确需使用，应单独以中断或阻塞方式实现，不要试图在本驱动里强加 DMA。

    init_finished 门控

    系统初始化完成前，接收事件只重启 DMA、不分发回调，避免早期未就绪的业务对象被调用。

    与同工程其它 BSP 的对比

    维度 UART BSP SPI BSP CAN BSP
    拓扑 点对点 点对点 总线多设备
    路由依据 huart->Instance 分支 hspi->Instance 分支 CAN ID 查表
    注册接口 UART_Init(huart, cb) SPI_Init(hspi, cb) BSP_CAN_RegisterCallback(id, cb)
    回调签名 (uint8_t*, uint16_t) (uint8_t*, uint8_t*, uint16_t, uint16_t) (hcan, id, data, len)
    缓冲策略 双缓冲收流 收发等长缓冲 按 ID 分发
