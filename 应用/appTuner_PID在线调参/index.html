    appTuner — PID 在线调参方案草稿（未接入当前主线）

    方案介绍

    这是一份尚未实现的在线调参方案：设想通过 EricTool 调整最多四路 PID，并将参数保存到 W25Q64JV。下文用于讨论数据模型、通信和存储流程，不提供可直接调用的 appTuner 接口。

    当前可用范围

    H7_BSP 主线已通过 Transport_Task 提供 EricTool 上行遥测，文本解析器也能识别 name:value#；在线赋值和 Flash 参数持久化尚未接入。图中的 App_Tuner_*、PID_Tuner_Manager_t 和 Flash_Task 均为拟议组件。

    拟议的三区数据模型

    appTuner 将 PID 参数按读写权限和存储介质分为三个区域：

    区域 存储 写入方 字段
    Flash 持久区 W25Q64JV EricTool (写 Flash) + 上电恢复 K_P / K_I / K_D / K_F / Out_Max / I_Out_Max / Aspeed / Bspeed / SepThr / D_First / D_T
    RAM 实时区 SRAM EricTool (Target) / 外部代码 (Now) Target / Now
    只读遥测区 SRAM PID 计算后回填 Out / I_Out
    • D_T 可变不可调：代码中设置，不在 EricTool 字典中
    • Now 不在 EricTool 字典中：由电机编码器等外部代码直接写入
    • Out / I_Out 仅 TX 遥测，不接受下行指令

    拟议的多实例支持

    通过 PID_Tuner_Manager_t 管理最多 4 个 PID 实例：

    #define PID_TUNER_MAX 4

typedef struct {
    PID_Tuner_Instance_t instance[PID_TUNER_MAX];
    uint8_t active_index;  // 当前活跃实例, EricTool RX/TX 的目标
    uint8_t count;         // 已注册实例数
} PID_Tuner_Manager_t;

    每个实例独占一个 W25Q64JV Sector（4KB），互不干扰。切换实例只需改 active_index。

    拟议的 EricTool 协议

    下行指令字典（RX，11 项）

    方案拟沿用当前解析器的 variable:value# 文本格式；仍需接入接收回调与实际赋值逻辑：

    索引 指令名 对应字段 存储
    0 P K_P Flash
    1 I K_I Flash
    2 D K_D Flash
    3 F K_F Flash
    4 OutMax Out_Max Flash
    5 IOutMax I_Out_Max Flash
    6 Aspeed I_Variable_Speed_A Flash
    7 Bspeed I_Variable_Speed_B Flash
    8 SepThr I_Separate_Threshold Flash
    9 DFirst D_First（0/1） Flash
    10 Target Target RAM

    指数 0~9 修改时立即写入 RAM 并标记 dirty，由 Flash Task 异步提交。 指数 10 只写 RAM，不触发 Flash 写入。

    上行遥测通道（TX，13 通道）

    拟由传输任务发送 justfloat 帧；发送周期及能否稳定交付须实测，拟议通道顺序如下：

    通道 数据 通道 数据
    0 K_P 7 I_Variable_Speed_B
    1 K_I 8 I_Separate_Threshold
    2 K_D 9 Target
    3 K_F 10 Now
    4 I_Out_Max 11 Out
    5 Out_Max 12 I_Out
    6 I_Variable_Speed_A — —

    拟议的 Flash 持久化流程

    graph TD
    A["上电 Init"] --> B["Read_Data 从 Flash 读取"]
    B --> C{"K_P == NaN ?"}
    C -->|"是 (首次上电)"| D["Write_Flash_Defaults<br/>Set_Write_Enable → Erase → Write 默认值"]
    C -->|"否 (已有数据)"| E["保留 Flash 镜像"]
    D --> F["Push_Flash_Params_To_PID"]
    E --> F

    subgraph "运行时 (EricTool RX)"
        G["RX: P:2.5#"] --> H["a->flash.K_P = 2.5"]
        H --> I["a->pid->Set_K_P(2.5)"]
        I --> J["a->dirty = true"]
    end

    subgraph "异步提交 (Flash Task, 100ms 周期)"
        J --> K{"dirty && Is_Ready ?"}
        K -->|"是"| L["Set_Write_Enable"]
        L --> M["等待 Ready"]
        M --> N["Set_Sector_Erased"]
        N --> O["等待 Ready (~400ms)"]
        O --> P["Write_Data"]
        P --> Q["等待 Ready"]
        Q --> R["dirty = false"]
        K -->|"否"| S["下个周期重试"]
    end

    关键设计：Erase 耗时 ~400ms，在低优先级 RTOS 任务中执行，通过 osDelay 让出 CPU 给 PID 实时计算。

    空值检测：W25Q64JV 擦除后全为 0xFF，float 解析为 NaN。用 std::isnan(K_P) 判断首次上电，无需额外 Magic Number。

    拟议 API（当前不存在）

    注册与初始化

    // 注册 PID 实例（必须在 Init 之前）
App_Tuner_Register_PID(0, &motor_pid,  0x000000);  // PID_0, Sector 0
App_Tuner_Register_PID(1, &steer_pid,  0x001000);  // PID_1, Sector 1

// 模块初始化
App_Tuner_Init();  // USB + EricTool + 逐实例读 Flash + 推入 PID

    运行时接口

    // TX: 注册遥测指针（由 StatusTask 或调用方调用）
PID_Tuner.active_index = 0;  // 切到 PID_0
App_Tuner_TX();              // 覆盖 EricTool 遥测通道

// RX: EricTool 下行处理（由 USB CDC 回调驱动）
App_Tuner_RX();

// Flash Task: 独立 RTOS 任务入口
void StartFlashTask(void) {
    // 低优先级, 100ms 周期
    App_Tuner_Flash_Task();
}

// 外部写入 Now (电机编码器等)
PID_Tuner.instance[0].Now = encoder_value;

    结构体

    // Flash 持久化参数 (44 字节, 4 字节对齐)
typedef struct {
    float K_P, K_I, K_D, K_F;
    float I_Out_Max, Out_Max;
    float I_Variable_Speed_A, I_Variable_Speed_B, I_Separate_Threshold;
    Enum_PID_D_First D_First;
    float D_T;
} Flash_PID_Params_t;

// 单个 PID 实例
typedef struct {
    Flash_PID_Params_t flash;
    float Target, Now, Out, I_Out;
    Class_PID *pid;
    uint32_t flash_addr;
    bool dirty;
} PID_Tuner_Instance_t;

    待实现后的测试方案

    编译验证

    # 在 H7_BSP 项目根目录下
ninja -C build/Debug

    预期输出：目标构建与链接通过，无 error。

    功能测试（需硬件 + EricTool GUI）

    测试项 A — 下行调参

    • 步骤：EricTool GUI 发送 P:2.5#
    • 验证：PID 对象的 K_P 立即变为 2.5，遥测通道 0 显示 2.5

    测试项 B — Flash 持久化

    • 步骤：调参后断电重启
    • 验证：上电后 K_P 恢复为断电前值（而非默认值 1.0）

    测试项 C — 首次上电默认值

    • 步骤：擦除 W25Q64JV Sector 0，然后上电
    • 验证：K_P=1.0，其余 Flash 参数为 0

    测试项 D — 多实例切换

    • 步骤：active_index=0, 调 PID_0 → 切 active_index=1, 调 PID_1 → 切回 active_index=0
    • 验证：各自的参数独立持久化，互不干扰

    测试项 E — Now 外部写入

    • 步骤：电机转动时观察 EricTool 遥测通道 10 (Now)
    • 验证：Now 值随电机转动实时变化，且无法通过 EricTool 下行修改

    调参工作流

    graph TD
    A["上电"] --> B["从 Flash 恢复参数"]
    B --> C["EricTool 连接 USB CDC"]
    C --> D["上位机发送 P:1.5#"]
    D --> E["1ms 内 PID 生效"]
    E --> F["观察遥测波形"]
    F --> G{"满意 ?"}
    G -->|"否"| D
    G -->|"是"| H["等待 Flash Task 提交 (≤100ms)"]
    H --> I["可安全断电"]

    方案风险与限制（未板测）

    • Erase 粒度 4KB：W25Q64JV 最小擦除单位为 Sector，单次 Erase ~400ms
    • 写入吞吐：每次提交写入整个 Flash_PID_Params_t（44 字节），Page Program 约 0.7ms
    • dirty 去抖：Flash Task 100ms 周期，调参后最多 100ms 延迟才写入 Flash。掉电可能丢失最近 100ms 的改动
    • W25Q64JV 写入寿命：10 万次擦写，正常调参使用足够
    • 线程安全：Flash 写入仅由 Flash Task 执行，其他代码只操作 RAM。active_index 切换无锁保护，避免在 RX 中断中修改

    待实现后的测试计划

    前置条件

    • H7_BSP 硬件已正常启动，W25Q64JV 就绪
    • EricTool GUI 通过 USB CDC 连接，确认波形窗口有数据显示
    • 至少注册一个 PID 实例并完成 App_Tuner_Init()
    • 已扩展 Transport_Task 或其他接收链，注册 EricTool 回调并由应用处理下行指令
    • Flash_Task 已创建（处理异步提交）

    TC-01：编译验证

    • 操作：执行 ninja -C build/Debug
    • 预期：目标构建与链接通过，无 error

    TC-02：首次上电默认值验证

    • 操作：擦除 W25Q64JV 目标 Sector（如 0x000000），上电运行
    • 观测：EricTool 遥测通道 0 显示 K_P=1.0，通道 1~8 显示 0.0
    • 验证：默认值写入 Flash，从串口日志确认 Write_Flash_Defaults 执行

    TC-03：下行调参 — Flash 字段

    • 操作：EricTool GUI 发送 P:2.5#
    • 观测：遥测通道 0 立即变为 2.5
    • 验证：PID 输出可见变化（若 Target≠Now）

    TC-04：下行调参 — Target

    • 操作：EricTool GUI 发送 Target:100#
    • 观测：遥测通道 9 立即变为 100
    • 验证：PID 立即开始计算，Out 通道可见响应。dirty 不被标记

    TC-05：Flash 持久化 — 掉电恢复

    • 操作：调参后（如 P=2.5，Target=100），正常断电等待 5 秒，重新上电
    • 观测：上电后遥测通道 0 显示 2.5（而非默认值 1.0）
    • 验证：Flash 持久化正常。Target 不恢复（RAM only，上电后为 0）

    TC-06：Flash 持久化 — 异步提交窗口

    • 操作：发送 P:3.0# 后立即断电（1 秒内）
    • 观测：重新上电后 K_P 可能仍为旧值（未及提交）
    • 验证：Flash Task 的 100ms 去抖周期有效。正常调参应等 1 秒以上再断电

    TC-07：多实例隔离

    • 操作：
      • active_index=0，发送 P:2.0# → PID_0 生效
      • active_index=1，发送 P:3.0# → PID_1 生效
      • 断电重启，切回 active_index=0，观察 K_P
    • 预期：PID_0 恢复 2.0，PID_1 恢复 3.0，互不干扰

    TC-08：Now 保护

    • 操作：EricTool GUI 发送 Now:50#
    • 预期：Now 不在字典中，指令被忽略（Variable_Index=-1）。Now 仍由外部代码控制

    TC-09：OutMax / IOutMax 限幅

    • 操作：注册 PID 实例，Target=100，Now=0。先不加限幅观察 Out 满幅输出。发送 OutMax:10#
    • 观测：遥测通道 11 (Out) 被限制在 [-10, 10] 范围内

    TC-10：变速积分

    • 操作：发送 Aspeed:5# Bspeed:20#，观察当 |error| 在 5~20 之间时积分项权重被线性缩小
    • 观测：遥测通道 12 (I_Out) 随误差大小非线性变化

    TC-11：微分先行

    • 操作：发送 DFirst:1#，然后快速改变 Target
    • 观测：微分冲击消失（与 DFirst=0 时对比）
